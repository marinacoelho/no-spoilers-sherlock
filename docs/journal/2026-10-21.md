## 3. Technical Decisions

1. **Strict Two-Layer Modular Split (`AppCore` vs App Target)**: Isolated all domain models, spoiler-filtering rules, and persistence abstractions inside `frontend/apple/Packages/AppCore` so business logic is testable via `swift test` without simulator overhead.
2. **iOS 26+ Native Liquid Glass Adoption**: Standardized interactive surfaces on native iOS 26 APIs (`GlassEffectContainer`, `.glassEffect()`, `.glassProminent` button styles, and `.glassEffectID` with `@Namespace`) rather than legacy custom blur materials.
3. **App Identity & Entry Point Alignment**: Configured the bundle display name as `"No Spoilers, Sherlock"` and named the `@main` app struct `NoSpoilersSherlockApp` to maintain clean Swift conventions and user-facing brand consistency.
4. **Swift 6 Strict Concurrency & Swift Testing**: Enforced `Sendable` conformance and actor isolation across `AppCore`, paired with modern Swift Testing (`@Test`, `#expect`) instead of legacy `XCTest`.

## 4. Blockers & Resolutions

- **Critic Council Specification Findings**: The 4-critic review surfaced edge-case ambiguities around spoiler boundary thresholds, concurrency isolation, and target naming. Resolved prior to implementation by updating both `prd-0001-no-spoilers-sherlock-ios.md` and `adr-0001-no-spoilers-sherlock-ios-architecture.md`.
- **Adversarial Boundary & Concurrency Edge Cases**: Red-team testing (`@adversarial-tester`) exposed 5 subtle boundary conditions in episode/chapter progress clamping, malformed input handling, and state persistence synchronization. Resolved by hardening `AppCore` validation logic and locking in regression coverage across 22 Swift Testing unit tests.
